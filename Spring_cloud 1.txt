Spring Cloud
-------------------
Spring Cloud is a framework built on top of Spring Boot that helps developers build microservices-based distributed systems easily.
It provides ready-made tools to solve common challenges in microservices, such as:
Service discovery
Configuration management-config server
Load balancing
Fault tolerance
API gateway routing
Distributed tracing

Spring Boot builds microservices, and Spring Cloud connects and manages them.
Why Spring Cloud is Needed
-------------------------------------
When building microservices, problems arise such as:
How services find each other
How to manage configurations
How to handle failures
How to route requests
How to monitor services
Spring Cloud solves these using prebuilt components.

Key Features of Spring Cloud
-------------------------------------
1)Service Discovery
Allows services to find each other automatically.
Uses:
Netflix Eureka
Benefits:
No need to hardcode service URLs
Dynamic registration of services
Example:
Order Service finds Payment Service automatically.

2)Centralized Configuration
Stores configuration in one central place.
Uses:
Spring Cloud Config
Benefits:
Update configs without restarting services
Maintain environment-specific configs

3)Load Balancing
Distributes traffic across multiple service instances.
Uses:
Spring Cloud LoadBalancer
Benefits:
Improves performance
Increases availability

4)Fault Tolerance
Handles service failures gracefully.
Uses:
Resilience4j
Features:
Circuit breaker
Retry
Timeout
Rate limiter

5)API Gateway
Single entry point for all services.
Uses:
Spring Cloud Gateway
Benefits:
Routing
Authentication
Logging
Rate limiting

6)Distributed Tracing
Tracks requests across multiple services.
Uses:
Spring Cloud Sleuth
Often integrated with:
Zipkin

7)Messaging Support
Enables communication between services.
Uses:
Spring Cloud Stream
Supports:
Kafka
RabbitMQ

8)Security Support
Provides secure microservice communication.
Uses:
OAuth2
JWT
Spring Security

Service Discovery in Microservices
---------------------------------------------
Service Discovery is one of the most important concepts in microservices, especially when using Spring Cloud with Netflix Eureka
What is Service Discovery?
----------------------------------
Service Discovery is the process by which microservices automatically find each other without hardcoding IP addresses or URLs.
Service Discovery helps one microservice locate another microservice automatically.
Why Service Discovery is Needed
------------------------------------------
In microservices,
Each service runs independently
Each service may run on:
Different machines
Different ports
Multiple instances
IP addresses may change frequently

Without service discovery:
Order Service -> http://localhost:8081
If the port changes -> system breaks

With service discovery:
Order Service -> user-service
Service registry finds the correct instance

How Service Discovery Works
Typical components:
Service Registry
Service Provider
Service Consumer

1)Service Registers Itself

User Service starts and registers with Netflix Eureka
 
user-service -> register ->Eureka
Registry stores:
Service Name
IP Address
Port

2) Consumer Requests Service
Example:
Order Service needs User Service
 
order-service ask -> Eureka -> user-service location

3) Communication Happens
Eureka returns:
 
user-service-> localhost:8081
Order service calls:
 http://localhost:8081/users

Components in Service Discovery
Service Registry
-----------------------
Stores all available services.
Example:
Netflix Eureka
Responsibilities:
Register services
Maintain service list
Provide service location
Service Provider
-----------------------
A microservice that registers itself.
Example:
Order Service -> User Service
Finds location through registry.

Types of Service Discovery

Client-Side Service Discovery
----------------------------------------
Used in Spring Cloud with Eureka.
Tools:
Netflix Eureka
Spring Cloud LoadBalancer
Flow:
 
Client -> Service -> Eureka ->Target Service

Service asks registry
Gets service instance
Calls service directly
Example:
user-service -> Eureka -> payment-service
Used in:
Spring Cloud

Server-Side Service Discovery
------------------------------------------
Uses an API gateway or load balancer.
Tools:
Spring Cloud Gateway flow:

 
Client -> Gateway -> Eureka -> Service

Client calls Gateway
Gateway finds service
Gateway routes request

Client vs Server-Side Discovery
-----------------------------------------
Feature                        Client-Side         Server-Side
Who finds service        Client                  Gateway
Load balancing            Client                  Gateway
Complexity                  More                    Less
Example                       Eureka Client     API Gateway

Advantages of Service Discovery
------------------------------------------
Automatic service registration
No hardcoded URLs
Supports scaling
Handles dynamic environments
Improves reliability

Challenges
----------------
Registry failure risk
More network communication
Requires monitoring

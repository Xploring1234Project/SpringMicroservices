The 12-Factor App is a set of principles for building modern, scalable, maintainable, and cloud-native applications.
 Originally designed for SaaS applications, it’s widely applied today to microservices architectures due to its emphasis on portability, 
robustness, and ease of deployment.

1. Codebase
“One codebase tracked in revision control, many deploys”

Each microservice should have its own code repository.
Avoid monolithic codebases shared between services.
Use version control (e.g., Git).

2. Dependencies
“Explicitly declare and isolate dependencies”

Declare all dependencies in a manifest (e.g., pom.xml for Java, package.json for Node.js).
Use dependency isolation (e.g., Docker, virtual environments).


3. Config
“Store config in the environment”

Configuration (e.g., credentials, URLs) should come from environment variables.
Avoid hardcoding or storing configs in codebase.

 4.Backing Services
“Treat backing services as attached resources”

Databases, message queues, and caches should be treated as external resources.
Interact with them via configuration (e.g., connection strings), not hardcoded URLs.

5. Build, Release, Run
“Strictly separate build and run stages”

Build: Compile or package your code.
Release: Combine build with configuration/environment.
Run: Execute the app in the environment.
Avoid mixing these stages.

6. Processes
“Execute the app as one or more stateless processes”

Microservices should be stateless.
Use databases or caches for state.
Enables scaling and resilience.

7. Port Binding
“Export services via port binding”

Each microservice should self-contain a web server and expose services via a port (e.g., HTTP, gRPC).
No reliance on external web servers like Apache or Tomcat.

8. Concurrency
“Scale out via the process model”

Design services to be horizontally scalable.
Use multiple instances of microservices for concurrency and fault tolerance.

9. Disposability
“Maximize robustness with fast startup and graceful shutdown”

Fast boot time and graceful shutdown enable:
Rapid scaling
Smooth deployment
Better fault recovery
Helps with container orchestration (e.g., Kubernetes)

10. Dev/Prod Parity
“Keep development, staging, and production as similar as possible”

Minimize differences between environments.
Use containerization .

11. Logs
“Treat logs as event streams”

Microservices should write logs to stdout/stderr.
Use external tools (e.g., ELK stack, Fluentd) for aggregation and analysis.
Avoid writing to files inside containers.

12. Admin Processes
“Run admin/management tasks as one-off processes”

Tasks like DB migrations, data repair, or cache warm-ups should be run as one-off processes.
These should use the same codebase and environment as the microservice.

Why 12-Factor Matters for Microservices
--------------------------------------------------
Encourages independent deployment and scaling.
Supports resilience and observability.
Enables continuous delivery and cloud-native practices.
